# kb-intake contract requests

Requests from kb-core for changes to the kb-intake delivery package contract. kb-core never changes kb-intake;
each request is decided by the project owner and, if accepted, implemented in kb-intake. Until then kb-core works without it.

| ID | Date | Request | Kind | Why kb-core needs it | Behaviour without it | Status |
|---|---|---|---|---|---|---|
| CR-1 | 2026-10-26 | Add an optional `color` (sRGB hex, e.g. `"#df271c"`) to `regions.font` | Additive (contract v2) | Annual reports mark note headings by colour. kb found them by reading PDF span colours, which kb-core may not do. Colour lets the annual-report profile separate note headings from numbered body text without issuer-specific values (a note heading must differ from the document's dominant body-text colour). | Note headings rely on numbering, font size and boldness only. The tree-eval stop rule still applies. | Open (raised by the project owner in PR #1 review) |
| CR-2 | 2026-10-28 | Add an `access` label to the package: `manifest.metadata.access` for the document and an optional `access` on `regions` (and `tables`) for blocks, each `{classification: public\|internal\|confidential\|restricted, domains: [string], owner: string, embargo_until: ISO-8601 timestamp with offset \| null}` | Additive (contract v2.x) | Round 2 W3 permissions (decision D1). Labels belong to the source system that knows the document's sensitivity; kb-core only enforces them (filters inside every route, counts over the visible scope, facts from visible observations, audit). The block label lets a sensitive section of an otherwise public report be hidden. | kb-core reads simulated labels from `config/access_labels.yaml` (document patterns, block title/page rules), marked `label_source: overlay`. A document still needs classification and owner to import. When CR-2 lands, intake labels take precedence (`label_source: intake`), the overlay can only raise them, and the overlay is deleted. | Open (raised in round 2 W3) |
